# 新加坡跨境数据检查表（上线前）

> 这是给隐私/法律负责人和工程 owner 的事实核对表，不是对新加坡或
> 其他法域的适用法律、控制者/处理者身份或合规性的结论。逐项确认后
> 才能申请开启生产采集、模型或跨境传输。

## 流程与责任

- [ ] 画出按 `site_id`、数据分类、来源、目的地、处理者和子处理者的
      数据流图；包含 Frappe、Observer、对象存储、备份、日志、支持和模型。
- [ ] 指定业务数据 owner、平台 owner、隐私/DPO 联系人、信息安全 owner
      和 incident 联系人；记录新加坡实体与其他实体的角色。
- [ ] 隐私/法律负责人已确认需适用的 PDPA、通信、劳动、财务记录、出口
      或其他法域规则，并把依据/版本/日期放入评审记录。

## 数据、通知与依据

- [ ] 逐字段标注 `Public`/`Internal`/`Confidential`/`Restricted`，确认
      原始通信、证据、个人标识、订单/财务快照和凭据不被误归类。
- [ ] 每个摄取目的有通知/同意或其他依据记录；撤回、限制、访问、删除
      和导出请求有负责人、时限和失败升级路径。
- [ ] 模型供应商、对象存储、支持人员和日志系统的最小字段范围已获批；
      未批准的原文不得进入提示词或诊断日志。

## 传输与合同

- [ ] 识别每条跨境传输的发送方、接收方、地点、子处理者、数据类别、
      目的、频率、加密和密钥持有方。
- [ ] 法律负责人确认符合适用要求的跨境机制/可比保护、DPA 或其他合同
      条款，并确认供应商变更通知与审计权；工程清单不替代该确认。
- [ ] 记录数据驻留、备份恢复、灾备切换、运维支持和模型临时处理的
      地域；默认禁止未列明目的地。

## 安全与运营

- [ ] 站点/Observer 分区、最小权限、密钥管理、密钥轮换、访问日志、
      webhook 防重放、上传隔离和供应链锁定均有测试证据。
- [ ] 保留、删除、导出和 legal hold 在两套数据平面及备份/索引中有
      可追溯回执；定义撤回后的停止处理动作。
- [ ] 已定义疑似泄露、误传、供应商故障和模型越权的响应流程；法律负责
      人确认适用的评估、通知对象和通知时限，不在工程文档中自行下结论。
- [ ] 完成一次仅 fixture/合成数据的演练；生产采集和真实模型仍为关闭状态。

## 放行证据与决定

- [ ] 风险、例外、剩余风险、owner、到期日和回滚开关已记录。
- [ ] Gate 评审明确 `GO`、`CONDITIONAL` 或 `NO-GO`，并链接数据流图、
      合同/供应商审查、测试报告和负责人批准。没有这些证据时保持
      `NO-GO`，不以“工程已实现”推断法律允许。
