# 数据治理与生命周期控制

> 本文是工程控制清单，不是法律结论或法律意见。适用的隐私、通信、
> 劳动、财务记录和跨境要求由指定隐私/法律负责人确认并留存依据。

## 原则与责任

- 按目的最小化采集；每条观察事件有 `site_id`、`consent_basis`、
  `data_classification`、`retention_class` 和证据引用。
- 数据所有者（业务/租户）决定业务目的；平台管理员执行配置但不能
  改写证据；隐私/法律负责人确认适用依据、保留与跨境条件；审计角色
  只读检查。真实模型、生产采集和跨境传输在 Gate 0/1 默认关闭。
- 原始资料、提取事实、AI Draft、ApprovedCommand 是不同状态；状态变化
  必须可追溯、可回放、可拒绝。

## 数据分类

| 分类 | 例子（非穷尽） | 最低工程控制 |
|---|---|---|
| `Public` | 已批准公开品牌/产品资料 | 完整性、来源和版本记录；不得因为公开而绕过租户边界 |
| `Internal` | 工作项、非敏感配置、汇总指标 | 已认证用户、站点范围、审计日志 |
| `Confidential` | 客户联系人、报价上下文、业务计划、已审阅事实 | 最小角色、传输/静态加密、导出审批、访问日志 |
| `Restricted` | 原始通信、证据对象、个人标识、财务/订单快照、凭据、法律保全数据 | 默认拒绝、站点隔离、短时授权、不可进入浏览器缓存/普通模型上下文；密钥不得入库 |

分类可以向上提升，不能因处理方便而降级。原始通信和证据至少按
`Restricted` 处理，除非负责人记录了可复核的更低分类理由。

## 保留类别（工程映射）

具体期限由数据 owner/隐私或法律负责人批准；下表是防止漏删的工程
映射，不是法定期限：

| `retention_class` | 用途 | 到期动作 |
|---|---|---|
| `R0-ephemeral` | 解析队列、失败重试、待审隔离 | 处理成功或窗口到期后删除；失败项先转入可审计隔离 |
| `R1-operational` | 工作项、已审阅派生事实、非财务业务上下文 | 按批准的业务表检查 hold、争议和审计需求后删除/不可恢复化 |
| `R2-record` | 合同、订单/库存/财务快照、审计证据 | 按负责人批准的记录表执行；不得由默认清理任务推断期限 |
| `R3-legal-hold` | 保全范围内的原文、证据和关联日志 | hold 释放前禁止自动删除或覆盖；释放后重新评估为其他类别 |

## 同意、依据与撤回

1. 摄取前登记用途、数据主体/参与者范围、通知或同意状态及适用依据。
   合同中的 `consent_basis` 枚举为 `consent`、`contract`、
   `legal_obligation`、`legitimate_interest` 或
   `manual_import_pending_review`；不确定时进入待审隔离区。
2. `manual_import_pending_review` 不得触发模型、外发消息或正式命令。
3. 收到撤回或限制请求后：停止新增处理和模型使用；标记受影响事件、
   证据、派生事实和导出任务；通知数据所有者/隐私负责人；按批准的
   例外规则决定是否保留。撤回不应删除仍受有效法律保全约束的数据。
4. 每个决定记录请求人、范围、时间、执行人、保留理由、失败项和复核
   到期日；不以“已删除”替代实际执行证据。

## 保留、删除、导出与法律保全

- `retention_class` 对应一份经负责人批准的保留表；未配置期限的数据
  不得由未经批准的自动任务擅自删除。期限到达后先检查 legal hold、
  争议、审计和备份窗口，再执行分层删除/不可恢复化，并产生删除回执。
- 删除必须覆盖 Frappe 记录、Observer 原始对象、证据引用、派生缓存、
  搜索索引、导出临时文件和任务队列；不能删除的对象要记录原因与下次
  复核日期。备份按其独立保留策略到期覆盖，不作即时可见数据恢复。
- 导出仅限请求租户和批准范围；生成字段清单、脱敏记录、来源/哈希、
  生成时间、过期时间和下载审计。导出包不得包含凭据、其他租户对象或
  未经批准的原始内容。
- 法律保全创建 `hold_id`、范围、负责人、开始/释放时间和证据快照；
  保全期间暂停相关自动删除和覆盖，访问仅限授权人员并全量审计。释放
  必须由指定负责人确认，随后重新评估保留期限。

## 可审计证据

至少保存：分类/依据变更、同意和撤回处理、保留与删除回执、导出清单、
legal hold 生命周期、跨模块引用校验、审批命令和 break-glass 访问。
证据本身按其包含内容分类，不能用日志记录替代访问控制。

## Gate 状态

Gate 0/1 只验证 schema、隔离、策略和 fixture 行为；生产采集、真实模型
调用、真实金蝶数据和跨境传输均保持关闭。工程清单的存在不表示已完成
法律评估或已获监管批准。
